# review_edit

## 事前準備：レビュー対象の特定

レビューを開始する前に、以下の git コマンドを順に実行し、未ステージングの変更を把握してください。

```bash
# 変更があるファイルの一覧を取得
git diff --name-only

# 各ファイルの変更箇所（差分）を取得
git diff
```

取得した情報をもとに、**変更されたファイル**をレビュー対象とします。

---

## レビュー方針

- **変更箇所（diff に含まれる行）** は、以下の全観点で詳しくレビューしてください。
- **変更箇所ではない箇所**（同じファイル内の未変更部分）も読み、明らかに修正すべき問題があれば合わせて指摘してください。その場合は指摘フォーマットに `[既存コード]` と付記してください。

---

## 1. アーキテクチャ・レイヤー規則（Fintrack 固有）

- **Controller** にビジネスロジックが混入していないか
- **Repository** にビジネスロジックが混入していないか
- 呼び出し方向が `Controller → Service → Repository` になっているか
- 禁止パターンの有無を確認する：
  - Controller → Repository の直接呼び出し
  - Service → Service の呼び出し
  - Controller → Controller の呼び出し
  - Repository → Repository の呼び出し

## 2. データアクセス（Fintrack 固有）

- `JPA` / `@Entity` / `@Repository`（Spring Data）が使われていないか（NamedParameterJdbcTemplate + 手書き RowMapper のみ許可）
- `RowMapper` が適切に実装されているか（null チェック・型キャストの安全性）
- 全クエリに `userId` スコープが含まれているか（ユーザー間データ混在の防止）
- フィンガープリントによる重複チェックが正しく機能しているか（CSV 再インポート時の重複排除）
- `split_pattern_id` の意味（NULL=未分類 / 0=単一 / -1=手動分割 / 正値=パターンID）が正しく扱われているか

## 3. セキュリティ

- 認証・認可のバイパスが発生しないか（未ログインでのリソースアクセス）
- Spring Security の設定で保護すべきパスが漏れていないか
- CSRF トークンが無効化されていないか
- SQL インジェクション：NamedParameterJdbcTemplate のバインドパラメータを使っているか（文字列結合での SQL 組み立て禁止）
- 他ユーザーのデータへの不正アクセスが可能な実装になっていないか（userId チェック漏れ）
- パスワードは BCrypt でハッシュ化されているか

## 4. 例外処理・エラーハンドリング

- 想定される例外が適切にキャッチされているか
- `catch (Exception e) {}` のような握りつぶしがないか
- エラー情報がスタックトレースごとクライアントに露出していないか
- バリデーションエラーをユーザーに適切にフィードバックしているか
- トランザクション境界（`@Transactional`）が適切に設定されているか

## 5. Java 21 コード品質

- 可変状態の最小化：変数は可能な限り `final` にしているか
- `Optional` の適切な使用（`get()` の無防備な呼び出しがないか）
- Stream API・レコード・パターンマッチング等のモダン Java 機能を活かせているか
- nullability が明確か（`@Nullable` / `@NonNull` アノテーション、または Javadoc での明示）
- 不要なボイラープレートが残っていないか（Lombok 未使用なら手書きの getter/setter/constructor 等）
- メソッドが単一責務になっているか（長すぎるメソッドは分割を検討）
- マジックナンバー・マジック文字列が定数や Enum に切り出されているか

## 6. Spring Boot ベストプラクティス

- コンストラクタインジェクションを使っているか（フィールドインジェクション `@Autowired` は非推奨）
- Bean のスコープが意図どおりか（基本は Singleton、状態を持たせない）
- `@Transactional` のロールバック条件（デフォルトは RuntimeException のみ）を理解して使っているか
- プロパティ値は `@Value` か `@ConfigurationProperties` で外部化されているか（ハードコード禁止）
- Thymeleaf テンプレートで XSS のリスクがないか（`th:utext` の使用箇所を確認）
- リダイレクト先が外部 URL を許すオープンリダイレクトになっていないか

## 7. CSV インポート（Fintrack 固有）

- CSV パーサーが Apache Commons CSV を使っているか
- 各金融機関フォーマットの差異（楽天銀行・楽天カード・楽天デビット・みずほ・三菱UFJ）を正しく吸収しているか
- 不正な CSV 行（フィールド欠損・型不整合）を安全にスキップまたはエラー通知しているか
- フィンガープリント生成ロジックが一意性を保証できているか

## 8. パフォーマンス

- N+1 クエリが発生していないか（ループ内で都度 DB アクセスしていないか）
- 大量データを一括フェッチして全件メモリに乗せていないか
- 不要なトランザクションの長時間保持がないか

## 9. 命名・可読性

- クラス・メソッド・変数名がドメイン用語（BankTransaction / CardTransaction / Asset 等）と一致しているか
- メソッド名が動詞 + 目的語で意図を表しているか
- 省略しすぎた変数名（`t`、`tmp` 等）がないか
- パッケージ構成（controller / service / repository / domain / csv / config）に沿った配置か

## 10. デッドコード・不要な定義

- 定義されているが、どこからも呼び出されていないメソッドがないか（未使用メソッド）
- ドメインクラスに実際には使われていないフィールドが定義されていないか（不要フィールド）
- SQL クエリで `SELECT *` を使っていないか（必要なカラムを明示的に列挙すること）
